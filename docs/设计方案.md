# RoxCSS 设计方案

## 一、定位

运行时原子 CSS 引擎。模板字符串标签函数，动态解析类名并注入 CSS 规则。

- 零构建，零配置
- 框架无关
- 类名透传，DevTools 调试友好

---

## 二、API

```typescript
import { createRox } from "roxcss";

const rox = createRox({
  modifiers: {
    md: (className: string, selector: string, cssDecl: string) =>
      `@media (min-width: 768px) { ${selector} { ${cssDecl} } }`,
    dark: (className: string, selector: string, cssDecl: string) =>
      `.dark ${selector} { ${cssDecl} }`,
  },
  matchers: {
    flex: {
      "": (...args: string[]) => `display:flex`,
      space: {
        "": (v: string) => `justify-content:space-${v}`,
        between: () => `justify-content:space-between`,
        around: () => `justify-content:space-around`,
      },
    },
    p: (v: string) => `padding:${v}`,
    m: (v: string) => `margin:${v}`,
    bg: (v: string) => `background:${v}`,
    border: (type: string, width: string, color: string) => `border:${type} ${width} ${color}`,
  },
});

const className = rox`
  flex
  p-4px
  hover:bg-blue
  md:flex-space-between
  border-1px-solid-red
`;
// 返回: "flex p-4px hover:bg-blue md:flex-space-between border-1px-solid-red"
```

## 三、核心引擎

### 3.1 输入处理

```typescript
const raw = String.raw({ raw: strings }, ...values);
const tokens = raw.split(/\s+/).filter(Boolean);
```

- `String.raw` 保留原始字符串，不做转义
- 按空白字符拆分，过滤空字符串

### 3.2 Token 解析

```
token = 'md:hover:focus:bg-blue'
```

按 `:` 分割：

```
parts = ['md', 'hover', 'focus', 'bg-blue']
```

- **最后一段** → 匹配部分（`bg-blue`），用于查找 matcher
- **前面所有段** → 遍历判断：
  - 在 `modifiers` 注册表中 → 环境修饰符
  - 不在注册表中 → 伪类

### 3.3 环境修饰符

`modifiers` 只处理**规则层面**的包裹（媒体查询、容器查询、主题选择器等），不处理选择器层面的伪类。

```typescript
const modifiers = {
  md: (className, selector, cssDecl) => `@media (min-width: 768px) { ${selector} { ${cssDecl} } }`,
  dark: (className, selector, cssDecl) => `.dark ${selector} { ${cssDecl} }`,
};
```

**限制：最多一个环境修饰符。** 如果 token 中出现多个注册在 `modifiers` 中的段，匹配失败。

### 3.4 伪类

不在 `modifiers` 注册表中的前缀段全部视为伪类，按顺序拼接到选择器上：

```
token = 'hover:focus:bg-blue'
选择器 = '[class~="hover:focus:bg-blue"]:hover:focus'
```

伪类不需要注册，天然支持任意多个的组合。

### 3.5 Matcher 查找与调用

匹配部分按 `-` 分割成段列表，在 matcher 嵌套结构中逐段查找：

```
matchPart = 'flex-space-between'
segments = ['flex', 'space', 'between']
```

**遍历规则：**

1. 从 `matchers` 根对象开始，使用当前段作为键查找
2. 如果当前段在对象中有精确键，进入该节点，段指针前移
3. 重复步骤 2，直到以下任一情况发生：
   - **当前节点是函数**：立即调用它，参数为从当前段开始的所有剩余段（展开传入）
   - **段列表耗尽**：调用当前节点的 `''`（如果没有则匹配失败），参数为空
   - **当前段无精确匹配**：调用当前节点的 `''`，参数为从当前段开始的所有剩余段
   - **当前节点无 `''` 且无精确匹配**：匹配失败

**函数简写：** 函数形式等价于 `{ '': fn }`。两者完全等效。

```typescript
p: (v) => `padding:${v}`
// 等价于
p: { "": (v) => `padding:${v}` }
```

### 3.6 规则生成

```
无环境修饰符：
  [class~="token"]:pseudo1:pseudo2 { cssDecl }

有环境修饰符（以 md 为例）：
  @media (min-width: 768px) { [class~="token"]:pseudo1:pseudo2 { cssDecl } }
```

流程：

1. 构建基础选择器：`[class~="${token}"]` + 所有伪类按顺序拼接
2. 如果有环境修饰符，调用 `modifier(token, selector, cssDecl)` 生成完整规则
3. 如果没有，直接拼接 `selector { cssDecl }`

### 3.7 注入

```typescript
if (!injected.has(token) && !failed.has(token)) {
  // 解析并尝试注入
}
```

**批量写入**：一次 `rox` 调用内产生的新规则收集为 batch，调用结束时拼接成一段 CSS 文本，经 `adoptStyles`（`CSSStyleSheet` + `replaceSync` + `adoptedStyleSheets.push`）一次性写入，保持同步语义——调用返回时规则已生效。

不使用逐条 `insertRule`：在"插入与强制布局交替"场景下会退化为 O(N²) 的同步样式重算（见 docs/性能分析.md 缺陷记录 P0）。

无 DOM 环境（SSR/测试）下仅记录规则到内存，供 `getCSS()` 读取，不实际写入。

### 3.8 返回

```typescript
return tokens.join(" ");
```

原始 token 原样返回，无论匹配成功或失败。失败时返回原 token，不注入任何规则。

## 四、类型定义

```typescript
type MatcherFunction = (...args: string[]) => string | null;

type MatcherNode =
  | MatcherFunction
  | {
      [key: string]: MatcherNode;
    };

type Modifier = (className: string, selector: string, cssDecl: string) => string;

interface RoxOptions {
  matchers: Record<string, MatcherNode>;
  modifiers?: Record<string, Modifier>;
}

interface RoxInstance {
  (strings: TemplateStringsArray, ...values: unknown[]): string;
  getCSS(): string;
}
```

## 五、匹配器系统

### 5.1 基本形式

```typescript
// 函数形式：等价于 { "": fn }，捕获所有剩余段
const matchers = {
  p: (v: string) => `padding:${v}`,
};

// 嵌套对象：逐段精确匹配
const matchers = {
  flex: {
    "": (...args: string[]) => `display:flex`,
    space: {
      "": (v: string) => `justify-content:space-${v}`,
      between: () => `justify-content:space-between`,
      around: () => `justify-content:space-around`,
    },
  },
};
```

### 5.2 函数不是终点

任何函数出现在任何位置，都会吞掉它之后的所有内容。没有“终点节点”概念。

```typescript
{
  flex: {
    between: () => "...",  // 吞掉 flex-between- 后面的所有
    space: {
      between: () => "...",  // 吞掉 flex-space-between- 后面的所有
      "": (v) => "...",  // 吞掉 flex-space- 后面的所有
    },
  },
}
```

`flex-between-extra` → 调用 `between('extra')`
`flex-space-between-x` → 调用 `space.between('x')`
`flex-space-center` → 调用 `space['']('center')`

### 5.3 参数传递

叶子函数收到的参数是**从当前段开始的所有剩余段**，按顺序展开传入。

```
p-9px
segments = ['p', '9px']
'p' 是函数 → 调用 ('9px')

flex-space-center
segments = ['flex', 'space', 'center']
'flex' → 进入节点
'space' → 进入节点
'center' 无精确匹配，'space' 节点有 '' → 调用 ''('center')

flex-space-between
segments = ['flex', 'space', 'between']
'flex' → 进入节点
'space' → 进入节点
'between' → 精确匹配，是函数 → 调用 between()，参数为空

flex
segments = ['flex']
'flex' 是函数 → 调用 ()，参数为空
```

### 5.4 匹配失败

以下情况匹配失败，返回原 token：

- 遍历到某个节点，当前段无精确匹配，且该节点无 `''`
- 段列表耗尽，但最终节点不是函数且无 `''`
- matcher 函数返回 `null`

## 六、修饰器

修饰器只处理**环境包裹**，不处理伪类。

```typescript
const modifiers = {
  md: (className: string, selector: string, cssDecl: string) =>
    `@media (min-width: 768px) { ${selector} { ${cssDecl} } }`,

  dark: (className: string, selector: string, cssDecl: string) =>
    `.dark ${selector} { ${cssDecl} }`,
};
```

- 接收类名、基础选择器和 CSS 声明
- 返回完整的 CSS 规则字符串
- 内部逻辑完全自由
- 最多一个环境修饰符

## 七、完整示例

输入：

```
rox`hover:bg-blue p-4px border-1px-solid-red md:flex-space-between`
```

解析：

| token                   | 环境修饰符 | 伪类    | 匹配结果                      | CSS 声明                        | 规则                                                                                                 |
| ----------------------- | ---------- | ------- | ----------------------------- | ------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `hover:bg-blue`         | —          | `hover` | `bg('blue')`                  | `background:blue`               | `[class~="hover:bg-blue"]:hover { background: blue; }`                                               |
| `p-4px`                 | —          | —       | `p('4px')`                    | `padding:4px`                   | `[class~="p-4px"] { padding: 4px; }`                                                                 |
| `border-1px-solid-red`  | —          | —       | `border('1px','solid','red')` | `border:1px solid red`          | `[class~="border-1px-solid-red"] { border: 1px solid red; }`                                         |
| `md:flex-space-between` | `md`       | —       | `flex.space.between()`        | `justify-content:space-between` | `@media (min-width: 768px) { [class~="md:flex-space-between"] { justify-content: space-between; } }` |

返回：

```
"hover:bg-blue p-4px border-1px-solid-red md:flex-space-between"
```

## 八、缓存

```typescript
private injected = new Set<string>();  // 已成功注入的 token
private failed = new Set<string>();    // 匹配失败的 token
```

- `injected`：避免重复注入相同规则
- `failed`：避免重复解析已知失败的 token
- 类名就是 token 本身，不需要映射

## 九、错误处理

在开发环境中，以下情况输出警告：

- token 中存在多个环境修饰符
- matcher 匹配失败（未找到匹配路径）
- matcher 函数返回 `null`

```typescript
if (!matcher) {
  if (globalThis.process?.env?.NODE_ENV === "development") {
    console.warn(`[roxcss] 未找到匹配器 "${matcherName}"（来自 token "${token}"）`);
  }
  return token;
}
```

## 十、规则生成

一律使用属性选择器：

```css
/* 普通 */
[class~="flex"] {
  display: flex;
}

/* 伪类 */
[class~="hover:bg-blue"]:hover {
  background: blue;
}

/* 伪类链 */
[class~="hover:focus:bg-blue"]:hover:focus {
  background: blue;
}

/* 环境修饰器 */
@media (min-width: 768px) {
  [class~="md:flex"] {
    display: flex;
  }
}

/* 环境修饰器 + 伪类 */
@media (min-width: 768px) {
  [class~="md:hover:bg-blue"]:hover {
    background: blue;
  }
}
```

## 十一、合法字符与安全

### token 的字符集

token 直接嵌入 CSS 属性选择器 `[class~="..."]`，以下字符会破坏选择器，导致规则被浏览器静默丢弃：

- `"`（双引号）：破坏属性选择器的引号配对
- `\`（反斜杠）：CSS 转义符，改变选择器语义
- 空白字符（空格、换行、制表符）：token 拆分的分隔符

建议 token 只使用：`A-Z a-z 0-9 - _ : . %`。

### 行为

含非法字符的 token 按"匹配失败"处理：返回原 token、不注入任何 CSS、开发环境输出警告。类名透传不受影响。

### 安全边界

类名来自开发者代码（模板字面量）时风险可控。**若 token 来自不可信输入**（如 `${}` 插值拼接 URL 参数、后端数据），需要注意：

- 构造的 token 若能匹配 matcher，且 matcher 将未清洗的输入拼进声明，`;` 或 `}` 可能注入额外 CSS 规则——所有运行时 CSS 库共有的注入面
- `"` 逃逸属性选择器属于此类
- 约定：**matcher 的返回值（cssDecl）视为可信代码**，不要将不可信输入直接拼进声明；token 插值输入应限制在白名单字符集内

## 十三、核心实现

当前实现结构：模块级纯函数 + `EngineContext` 传递实例状态，`createRox` 只负责初始化与返回。完整代码见 `src/core.ts`，以下为结构示意。

```typescript
import type { MatcherNode, Modifier, RoxInstance, RoxOptions } from "./types.ts";
import { adoptStyles } from "./dom.ts";

interface EngineContext {
  matchers: Record<string, MatcherNode>;
  modifiers: Record<string, Modifier>;
  injected: Set<string>;
  failed: Set<string>;
  rules: string[];
}

// 模块级纯函数：fail / parsePrefix / lookup / injectRule / resolveToken
// 通过 ctx 参数共享实例状态

export function createRox(options: RoxOptions): RoxInstance {
  const ctx: EngineContext = {/* 初始化实例状态 */};

  function rox(strings: TemplateStringsArray, ...values: unknown[]): string {
    const tokens = String.raw({ raw: strings }, ...values)
      .split(/\s+/)
      .filter(Boolean);
    const batch: string[] = [];
    const result = tokens.map((token) => resolveToken(ctx, token, batch)).join(" ");

    if (batch.length) adoptStyles(batch.join("\n"));
    return result;
  }

  return Object.assign(rox, { getCSS: () => ctx.rules.join("\n") });
}
```

查找逻辑要点：

- 匹配段使用 `Object.hasOwn`（而非 `key in`）避免原型链误命中（如 `constructor`）
- 函数节点吞掉剩余所有段后调用，返回 `null` 视为失败
- 规则文本统一经 `adoptStyles` 批量写入 `adoptedStyleSheets`，无 DOM 环境跳过

# RoxCSS 配置设计

## 一、决策记录

- **单一默认配置**：`createConfig` 工厂函数提供，替代预设体系
- **值原样透传**：单位由调用者写全（`p-4px` 有效，`p-4` 生成无效的 `padding:4`）；值解析（rem 体系、颜色色板、字号表）作为后续可选增强
- **工厂函数而非静态对象**：多实例配置隔离（每次调用返回全新对象）、组合自定义（overrides 浅合并）
- **曾设计 minimal/unocss 双预设，已取消**：
  - `minimal` 过于简陋（仅十几个 matcher）
  - `unocss` 名不副实——roxcss 是运行时库，无法与编译时库（UnoCSS）完全对齐，用其名字会误导使用者
- 原 `unocss` 预设中的值解析逻辑（间距比例、色板、字号）不进入默认配置，留待后续以增强形式加入

---

## 二、配置形态

```typescript
// src/config.ts
import type { Preset } from "./types.ts";

export function createConfig(overrides?: Partial<Preset>): Preset {
  return {
    matchers: { ...base.matchers, ...overrides?.matchers },
    modifiers: { ...base.modifiers, ...overrides?.modifiers },
  };
}
```

- 返回全新对象，多实例互不共享引用
- 浅合并：第一层展开，自定义覆盖同名 matcher/modifier
- 嵌套的 matcher 子对象（如 `flex: {...}`）共享引用无害（纯函数数据）

用法：

```typescript
const rox = createRox(createConfig());

// 自定义覆盖默认
const rox2 = createRox(
  createConfig({
    modifiers: { lg: (_c, s, d) => `@media (max-width: 1024px) { ${s} { ${d} } }` },
    matchers: { custom: () => "..." },
  }),
);
```

## 三、默认配置内容

### modifiers（断点，静态媒体查询）

| 断点 | 查询                         |
| ---- | ---------------------------- |
| sm   | `@media (min-width: 640px)`  |
| md   | `@media (min-width: 768px)`  |
| lg   | `@media (min-width: 1024px)` |
| xl   | `@media (min-width: 1280px)` |

### matchers（minimal + example 实际使用集合并）

- **display**：`block`、`hidden`、`inline`（含 `inline-block`）、`flex` 系列、`grid`
- **flex/grid 布局**：`flex-col/row/wrap/center/1/auto/grow`、`items-*`、`justify-*`、`grid-cols-*`
- **间距**：`p/px/py/pt/pr/pb/pl`、`m/mx/my/mt/mr/mb/ml`、`gap`（多段值空格连接）
- **尺寸**：`w/h`、`max-w/h`、`min-w/h`
- **颜色**：`bg`、`text`（值原样，如 `bg-#ef4444`、`text-white`）
- **边框**：`border`（多段拼接）、`rounded` 系列
- **文本**：`center/left/right`、`bold`、`italic`、`uppercase/lowercase/capitalize`、`font-*`
- **位置/层级**：`relative`、`absolute`、`fixed`、`sticky`、`z`、`top/right/bottom/left`、`inset`
- **盒模型/效果**：`box-*`、`shadow`、`opacity`、`overflow-*`、`transition`、`animation`、`transform`、`cursor`
- **交互**：`cursor-*`、`pointer-events-*`、`select-*`

> 完整清单以 `src/config.ts` 为准，文档不重复维护。

## 四、值语义约定

- **值一律原样使用**：matcher 接收的段直接拼入声明，不解析、不换算
- **单位写全**：`p-4px`、`w-170px`、`gap-4px-8px`；纯数字（`p-4`）会生成无效 CSS，属调用方错误
- **多段值**：按顺序以空格连接（`pt-4px-8px` → `padding-top:4px 8px`）
- **待定增强**：纯数字 → rem、颜色色板、字号表等值解析能力，实现时直接增强 `config.ts`（不改形态）

## 五、与 UnoCSS 的关系

**只借鉴"类名 → CSS 的语义映射"，不照抄内部机制。**

| 维度     | UnoCSS（编译时）   | roxcss（运行时）                       |
| -------- | ------------------ | -------------------------------------- |
| 解析时机 | 构建期，成本一次性 | 每次调用，解析器复杂度直接进运行时     |
| 类名字符 | 无约束             | 进 `[class~="..."]` 选择器，字符集受限 |
| 值处理   | 链式处理器随便组合 | matcher 内自解析，复杂度需克制         |
| 变体     | 完整 variants 体系 | modifiers + 伪类前缀                   |

不照抄：`--un-*-opacity` 变量机制、处理器链、正则扫描体系、复合变体（`group-hover:` 等）。

官方测试（`unocss/packages-presets/preset-mini/test/`）不能直接运行（测内部 API），但可作为未来值解析实现的**行为验收基准**（改编输入/期望输出到 roxcss 测试）。

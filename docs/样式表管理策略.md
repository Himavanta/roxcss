# RoxCSS 样式表管理方案

## 决策记录

经过讨论与实测，确定以下原则：

- **不使用 `insertRule`**：P0 实测证明其在“插入-强制重算交替”场景下会退化为 O(N²)
- **方案 A 为滚动桶**：`<style>` 元素复用，单桶上限 1000 条，冻结后新建
- **方案 B 为每次新建**：`CSSStyleSheet` 对象每次 flush 新建，直接 push 到 `adoptedStyleSheets`
- **批量规则通过一次文本赋值写入**：无论是 `textContent` 还是 `replaceSync`，都是整体替换，不是逐条插入
- **同步语义**：`rox` 调用返回时，规则已生效
- **运行时特性检测自动选择方案 B 或回退方案 A**

---

## 方案 A：`<style>` 元素 + `textContent` + 滚动桶

### 模型

```
rox 调用 → 收集新规则到 batch
  → 检查活动桶是否有空间（≤1000 条）
  → 有空间：追加到 activeRules，整体 textContent 重写
  → 无空间（或首次）：冻结当前桶，创建新 <style> 作为活动桶
```

### 核心机制

维护一个**活动 `<style>` 元素**和其对应的规则文本数组。每次 flush 将新规则追加到数组，整体重写该元素的 `textContent`。当活动桶内规则数达到 **1000** 时，冻结它，创建新的 `<style>` 元素继续。

### 实现

```typescript
const MAX_SHEET_SIZE = 1000;

let activeStyle: HTMLStyleElement | null = null;
let activeRules: string[] = [];
let activeCount = 0;

function flush(batch: string[]) {
  const doc = getDocument();
  if (!doc) return;

  if (!activeStyle || activeCount + batch.length > MAX_SHEET_SIZE) {
    // 冻结当前桶，创建新桶
    activeStyle = doc.createElement("style");
    activeStyle.dataset.roxcss = "";
    doc.head.appendChild(activeStyle);
    activeRules = [];
    activeCount = 0;
  }

  activeRules.push(...batch);
  activeCount += batch.length;
  activeStyle.textContent = activeRules.join("\n");
}
```

### 性能特征

| 操作                  | 成本                                          |
| --------------------- | --------------------------------------------- |
| 追加新规则            | O(batch 大小)，与总规则数无关（只重写当前桶） |
| 单次 textContent 解析 | O(当前桶内规则数) ≤ O(1000)                   |
| 样式失效              | 每次 flush 1 次                               |
| 已有规则影响          | 无（旧桶冻结，不重写）                        |
| P0 退化风险           | 无（整体替换，非逐条 insertRule）             |
| 容器数量              | ceil(总规则数 / 1000)                         |

### 阈值选择：1000

| 维度                     | 数值   |
| ------------------------ | ------ |
| 单次重写解析成本         | <0.1ms |
| 最坏同步重算（80 元素）  | ~7ms   |
| 最坏同步重算（500 元素） | ~47ms  |
| 1 万规则时的容器数       | 10 个  |
| 5 万规则时的容器数       | 50 个  |

1000 的核心目标：**让单次重写和重算成本压缩到几乎无法感知的范围**。50 个 `<style>` 标签的 DevTools 噪音可接受。

## 方案 B：`CSSStyleSheet` + `replaceSync` + 每次新建

### 模型

```
rox 调用 → 收集新规则到 batch → new CSSStyleSheet() → replaceSync(batch.join("\n")) → adoptedStyleSheets.push(sheet)
```

### 核心机制

每次 flush 创建一个全新的 CSSStyleSheet 对象，写入本批规则，直接 push 到 `document.adoptedStyleSheets`。无滚动桶、无阈值、无复用。

### 实现

```typescript
function flush(batch: string[]) {
  const doc = getDocument();
  if (!doc) return;

  const sheet = new CSSStyleSheet();
  sheet.replaceSync(batch.join("\n"));
  doc.adoptedStyleSheets.push(sheet);
}
```

### 性能特征

| 操作         | 成本                                     |
| ------------ | ---------------------------------------- |
| 追加新规则   | O(batch 大小)                            |
| 新建容器成本 | 纯 JS 对象创建 + replaceSync + 数组 push |
| 样式失效     | 每次 flush 1 次                          |
| 已有规则影响 | 无（每个 sheet 只含本批规则）            |
| P0 退化风险  | 无（整体替换，非逐条 insertRule）        |
| 容器数量     | = flush 次数                             |

### 特点

- **零 DOM 节点**：不创建 `<style>` 元素，不触碰 DOM 树
- **DevTools 整洁**：adopted stylesheets 不在 Elements 面板堆积
- **结构最简单**：和当前实现同构，只是容器类型从 DOM 元素换成 JS 对象
- **容器数量线性增长**：`adoptedStyleSheets` 数组本身随调用次数线性增长。DevTools 的 Adopted Style Sheets 区同样堆积，只是从 DOM 节点转移到了数组。运行时性能影响极低

### 兼容性

- **需要 `adoptedStyleSheets` 为可写数组的实现**（约 Chrome 115+，2023 年起；同期 Firefox、Safari）
- 早期实现（Chrome 73–114 等）中 `adoptedStyleSheets` 是 FrozenArray 语义，`push` 会**静默无效**
- 需特性检测，不支持或旧实现时回退到方案 A

## 兼容性策略

### 支持范围说明

- **方案 B 使用 `push` 追加**，要求 `adoptedStyleSheets` 是**可写数组**（规范 2023 年更新，约 Chrome 115+ / 同期 Firefox、Safari）。早期实现（Chrome 73–114 等，FrozenArray 语义）下 `push` 会**静默无效**，此范围不在支持列表内
- **回退路径是方案 A**，保证所有浏览器可用（`<style>` + `textContent` 无版本门槛）
- **特性检测 `"adoptedStyleSheets" in doc` 只确认特性存在**，无法区分“可写数组”与“FrozenArray”实现；旧实现上会静默降级为“检测通过但 push 无效”。这是刻意接受的取舍——方案 B 只面向现代浏览器，旧环境的行为不保证

### 实现

```typescript
function supportsConstructableStylesheets(): boolean {
  const doc = getDocument();
  return !!doc && "adoptedStyleSheets" in doc;
}

function flush(batch: string[]) {
  const doc = getDocument();
  if (!doc) return;

  if (supportsConstructableStylesheets()) {
    // 方案 B：仅现代可写数组实现
    const sheet = new CSSStyleSheet();
    sheet.replaceSync(batch.join("\n"));
    doc.adoptedStyleSheets.push(sheet);
  } else {
    // 方案 A（回退）
    if (!activeStyle || activeCount + batch.length > MAX_SHEET_SIZE) {
      activeStyle = doc.createElement("style");
      activeStyle.dataset.roxcss = "";
      doc.head.appendChild(activeStyle);
      activeRules = [];
      activeCount = 0;
    }
    activeRules.push(...batch);
    activeCount += batch.length;
    activeStyle.textContent = activeRules.join("\n");
  }
}
```

## 两个方案的本质差异

| 维度         | 方案 A（滚动桶）         | 方案 B（每次新建）                          |
| ------------ | ------------------------ | ------------------------------------------- |
| 容器数量     | ceil(规则数 / 1000)      | flush 次数                                  |
| 容器复用     | 复用，直到满             | 不复用                                      |
| 单次写入成本 | O(当前桶大小)，上限 1000 | O(batch 大小)                               |
| DOM 节点     | 有（`<style>` 元素）     | 无                                          |
| 容器堆积位置 | DOM 树 / Elements 面板   | adoptedStyleSheets 数组 / DevTools 对应区域 |
| 复杂度       | 需要管理桶状态           | 最简单                                      |
| 兼容性       | 全部现代浏览器           | Chrome 115+ / 同期 Firefox、Safari          |

## 共享核心引擎

无论选择哪个方案，以下逻辑完全一致。

### Token 解析

```
token = 'md:hover:focus:bg-blue'
按 ':' 分割 → ['md', 'hover', 'focus', 'bg-blue']

最后一段 → matchPart = 'bg-blue'
前缀段：
  - 在 modifiers 中 → 环境修饰符（最多一个）
  - 不在 → 伪类（任意多个，顺序拼接）
```

### Matcher 查找

按 '-' 分割，嵌套结构逐段匹配：

- 函数节点 → 吞掉剩余段，调用
- 精确键（`Object.hasOwn`）→ 进入，指针前移
- 无精确键但有 `''` → fallback，参数为剩余段
- 段耗尽有 `''` → 调用，参数空
- 都不满足 → 匹配失败

### 规则生成

```
[class~="token"]:pseudo1:pseudo2 { cssDecl }

// 有环境修饰符时：
@media (min-width: 768px) { [class~="token"]:hover { cssDecl } }
```

### 缓存

- `injected: Set<string>` — 已成功注入
- `failed: Set<string>` — 匹配失败
- 类名即 token

### 类型定义

```typescript
type MatcherFunction = (...args: string[]) => string | null;

type MatcherNode =
  | MatcherFunction
  | {
      [key: string]: MatcherNode;
    };

type Modifier = (className: string, selector: string, cssDecl: string) => string;

interface RoxOptions {
  matchers: Record<string, MatcherNode>;
  modifiers?: Record<string, Modifier>;
}

interface RoxInstance {
  (strings: TemplateStringsArray, ...values: unknown[]): string;
  getCSS(): string;
}
```

### 错误处理

开发环境警告：

- token 多个环境修饰符
- matcher 匹配失败
- matcher 返回 `null`

```typescript
const isDev = typeof process !== "undefined" && process.env.NODE_ENV !== "production";

function warn(message: string) {
  if (isDev) console.warn(`[roxcss] ${message}`);
}
```

## 测试策略

- **Node 环境**：token 解析、matcher 查找、缓存、getCSS
- **浏览器（方案 B）**：Chrome 115+ / Firefox 近期 / Safari 近期
- **回退验证**：模拟 `adoptedStyleSheets` 不可用，验证方案 A
- **旧实现验证**：确认 Chrome 73–114 等 FrozenArray 环境下 `push` 静默无效，不保证行为
- **P0 回归**：插入-强制重算-插入交替场景，确认无退化
- **同步语义**：调用后立即 `getComputedStyle` 验证生效
